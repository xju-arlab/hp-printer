# RC6 重复安装修复

## 问题与依据

用户报告 RC5 安装报错 `A different printer already uses this name`，要求支持直接覆盖与多次重复安装。

旧代码在 Windows 中发现同名队列后，仅比较当前用户 `settings.json` 内的端口；记录缺失、JSON 带 BOM 或端口已改变，就会进入该错误分支。首次添加队列后，后续步骤失败也会留下队列而未保存端口。此处是依据代码定位的触发条件，未在用户报错的那台设备上复现。

本机只读查看：已有队列使用 Microsoft IPP Class Driver，WSD 端口的 `Printer UUID` 与本应用固定 UUID 一致；Windows PnP 中记录的 IPP 地址为本机 18765 打印桥。当前本机端口与 RC2 设置相符，不能据此断言用户报错设备的具体配置。

## 修复

- 根据 Windows 记录的设备 UUID 或打印桥地址识别已有队列，本地端口记录作为兼容回退；缺失、损坏或带 BOM 的设置可恢复。
- 已存在本应用队列时复用，写回当前端口；队列被重命名且只有一个匹配设备时恢复标准名称。
- 只有首次创建才设置 A4、黑白、单面。重装不删除队列、不清除作业、不修改用户打印偏好或默认打印机。
- 添加操作遇到错误时重新检查是否已经完成，允许对半途失败的安装重试。
- 相同安装包跳过 EXE 覆盖和后台重启；升级时先准备文件，等待旧程序释放占用，再原子替换。
- 丢失 PID 文件时按当前用户的安装路径和 agent 命令识别旧后台；替换失败时尝试恢复原后台。
- 同一用户的安装与卸载共用互斥锁，避免同时改写文件和快捷方式。
- 无关的同名打印机不删除，提示先重命名；本次修复不接管其他打印设备。

## 验收边界

本轮只读调查现有 Windows 配置，未运行安装/卸载或提交打印作业；未添加或手动执行测试。构建与既有 CI 的结果在发布后追加。重复安装、配置丢失恢复和升级仍需在实际客户端验收。

Pi 生产服务继续固定 RC3；只同步源码与记录，不修改 CUPS/USB 配置。
