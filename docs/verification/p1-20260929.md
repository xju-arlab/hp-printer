## IPP 重复属性

- 对原始 `ipp://localhost:60000/ipp/print` 运行标准 `get-printer-attributes.test`：`media-default=iso_a4_210x297mm`、`sides-default=one-sided` 各出现一次，无重复警告。
- 对 CUPS 队列 `ipp://localhost:631/printers/HP_DeskJet_4900` 运行同一测试：以上两个属性各出现两次、值相同；`ipptool` 分别报告其在 `printer-attributes-tag` 中重复。
- 原队列保存 A4、黑白、单面选项；新建临时 driverless 对照队列并设置相同选项后，两个属性仍各出现一次。另用生产 PPD 内容创建临时队列，CUPS 复制出的 PPD 与原文件无 diff，查询仍无重复。所有临时队列均已删除，生产队列状态未受影响。此前对生产队列重新生成 driverless PPD 并重启 CUPS 也未消除重复。
- 因此已排除 USB 代理原始响应、PPD 内容本身以及单纯“生产队列有 A4/单面选项”这几个解释；重复与现有 CUPS 生产队列对象/响应路径相关，确切原因未解决。Windows 对此响应完成了 `Validate-Job` 和一次真实队列提交，但不代表 RFC 8011 合规。未重建生产队列，避免改变既有队列身份和历史；后续修复前保留严格查询作为回归检查。

IPP 要求同一属性组中的属性名唯一；重复属性仍是已知协议缺陷。[RFC 8011](https://www.rfc-editor.org/rfc/rfc8011.html)

## Windows 系统打印机与作业

- Windows 11 build 26200；通过 `Add-Printer -IppURL http://192.168.5.87:631/printers/HP_DeskJet_4900` 添加 `HP DeskJet 4900 (Pi CUPS)`。
- 队列驱动为 Windows inbox 的 Microsoft IPP Class Driver（Microsoft，x64 Driver Store）；无需下载/安装 HP 厂商驱动。Windows 内部端口名为 `WSD-…`，注册信息标记为 IPP Port；实际目标以 Add-Printer 的 IPP URL 和 Pi CUPS 收到的客户端请求为准。
- `Get-PrintConfiguration` 显示默认纸张 A4、黑白、单面；Windows PrintCapabilities 提供 Color、Grayscale、Monochrome 和 A4 等纸型。CUPS 声明 300 dpi、仅 `one-sided`，接受 PDF、PCLm 和 PWG Raster 等格式。
- 提交一页非敏感链路测试 `P1 Pi CUPS driverless path check`。Windows job ID 4 状态 Complete/Retained；Pi CUPS job ID 3 收到 87040 bytes，访问日志三步均 `successful-ok`。CUPS 随后 idle。此时 USB 原始端点状态为 idle/none，但 CUPS 队列状态原因为 `media-empty-report`，尚未解释。
- 原有 `HP DeskJet 4900 series [601905]`（WSD）和 `HP DeskJet 4900 series (USB)` 均保留；系统默认仍为 USB 队列。新队列状态 Normal。
- 实测证明当前 Windows 版本可用内置 IPP 类驱动把作业交给 Pi CUPS，且用户确认测试页成功出纸；不代表已验收 Word、PDF 阅读器、其他 Windows 版本、彩色/多份或 protected print。

## 回退

1. Windows 仅删除队列 `HP DeskJet 4900 (Pi CUPS)` 即可撤销本机新增入口；不会改动默认队列或另外两条 HP 队列。
2. Pi 端关闭 `HP_DeskJet_4900` 的 shared 标记，按备份恢复 `/etc/cups/cupsd.conf`、原始 `printers.conf`、PPD 和 `/etc/ipp-usb/ipp-usb.conf`；运行 `cupsd -t` 后重启 cups/ipp-usb 并确认原 URI、队列状态。
3. 移除 `/etc/systemd/system/ipp-usb.service.d/10-hp-printer-guard.conf` 与 `/usr/local/sbin/hp-printer-ipp-usb-guard`，执行 `systemctl daemon-reload` 并删除 nftables 表 `inet hp_printer_ipp_guard`。只按需回退；保留端口隔离规则是当前安全边界。
