## 实现

- 安装器首页和登录页增加“注册账号”，在原窗口填写用户名、邮箱、密码、确认密码。
- `NativeRegistration` 仅调用固定 Authentik 公共注册 Flow，使用独立 Cookie/CSRF 会话，不使用管理 API，也不打开浏览器收集密码。用户名、邮箱、密码仍由服务端策略最终校验。
- 注册提交与验证错误保留输入；进入邮件验证阶段后清空密码。密码只经私有 IPC 与 HTTPS 请求传输，不写入配置或日志，不回显服务器返回的表单值。
- 用户点击邮件中的一次性链接完成验证，再在安装器点击“已验证，登录”。邮箱验证链接在用户的邮箱/浏览器中完成；此按钮只发起正常 OIDC 登录，不标记邮箱已验证，不直接签发令牌或授权打印。
- 邮件重发由用户点击触发，客户端间隔至少 60 秒；不自动重发，保留服务端限频。提交重试前重新读取同一会话阶段，若已进入邮件验证则不再次创建账号。
- 未知注册字段/阶段明确报错，不静默跳过新的验证要求。
- 私有 IPC 单行上限调整为 64 KiB，容纳两次输入密码的 JSON Unicode 转义；仍是有界输入。
- 保留默认浅色、小尺寸 Logo、登录重试保留输入和覆盖安装。

协议参考：[Authentik Prompt stage](https://github.com/goauthentik/authentik/blob/main/authentik/stages/prompt/stage.py)、[Email stage](https://github.com/goauthentik/authentik/blob/main/authentik/stages/email/stage.py)。
