## 2. 第一版需求

| ID | 需求 | 预期行为 |
|---|---|---|
| R01 | 稳定打印入口 | Windows 只连接树莓派；树莓派以 USB 控制打印机 |

## 3. 当前设计决策

已确认项标明在表内，其他为实施默认建议，后续可根据验收调整。

| ID | 决策 | 建议及理由 |
|---|---|---|
| D01 | 单一实际队列 | 每物理打印机一个 CUPS 队列，Windows/API 共用，管理数据库仅作投影 |
| D02 | 执行模式（已确认） | 自动按队列打印；管理员可暂停、取消、恢复，不设置审批放行流程 |
| D03 | 排队 | 相同优先级下由 CUPS 调度，不承诺任务准备/挂起/错误时严格到达顺序 |
| D04 | 语言/工程（已确认） | Python + uv；建议 Python 3.12、Typer、FastAPI、pycups/libcups，提交 uv.lock；详见 CLI 工程设计 |
| D05 | 本机服务 | systemd + SQLite WAL，CUPS 保留宿主机；暂不容器化 USB/驱动 |
| D06 | Windows 入口 | IPP Directed Discovery 优先，目标 URL 指向树莓派 CUPS 队列 |
| D07 | 地址 | 树莓派有线 LAN 优先、DHCP reservation/稳定 DNS；打印机不需局域网 IP |
| D08 | 打印权限（已确认） | 实验室 LAN 电脑直接打印，管理员登录管理；Windows 提交的用户名不是可信业务账号 |
| D09 | 管理访问 | CLI 管理员登录；API 默认仅环回访问，LAN 访问需 HTTPS 和授权；CUPS 后台不向普通客户端开放 |
| D10 | 数据保留 | 默认不保留完成任务的文档副本；短期历史元数据建议 30 天，待用户确认 |

## 4. 还需明确的问题

| 问题 | 影响/不阻塞的部分 |
|---|---|
| Q02：其他电脑的 Windows 版本、是否启用 Windows protected print？ | 当前电脑 Windows 11 build 26200 且支持 Add-Printer 的 IppURL 参数；其他客户端另验，不能自动关闭安全策略 |
| Q04：长期使用有线还是 Wi-Fi、是否可配置地址保留、客户端数量？ | 当前 LAN 经 wlan0；eth0 在另一网段，不能未经验证直接换默认路由 |
| 后续可选：是否需要准确个人归属、本人取消或强配额？ | 首版已选择 LAN 直接打印，不再阻塞第一版；以后如需要再验证认证打印链路 |
| Q06：管理员是谁，是否需要在其他电脑直接运行 CLI？ | 默认 SSH 到 Pi 执行 CLI；LAN CLI/API 访问在明确 TLS 与认证后开放 |
| Q07：必须支持的 A4/彩色/份数/双面、是否需耗材读数？ | 根据能力探测实测冻结；未知读数显示未知 |
| Q08：断纸/关机后是否由管理员确认恢复？历史和文件保留多久？ | 默认保守恢复，避免部分已打印文件重复输出 |

自动打印、LAN 直接打印/管理员登录和设备 OS/队列问题已回答，不再重复询问。部署时只需核对实验室网段和管理来源的具体配置值；本轮仅完成设计和检查，没有开放网络。连接定位信息已记录在设备基线中；密码、密钥和 SSH 控制会话不进入仓库。
