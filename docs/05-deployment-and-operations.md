# 05 部署、诊断与运维

[返回主计划](README.md) · [实机基线](00-current-device.md)

## 1. 部署目标

首个目标环境是现有 **Ubuntu 24.04.4 arm64 / Raspberry Pi 4B**。项目为 Python + uv，CUPS 和 ipp-usb 留在宿主机，管理后端作为独立 systemd 服务运行；不以 Docker 接管现有 USB 设备。已有 Docker 网络不是本项目依赖。

```text
/opt/hp-printer/releases/<version>/   Python 包、锁文件及原地创建的 .venv，运行用户不可写
/opt/hp-printer/current              当前版本引用
/etc/hp-printer/                     受限配置、令牌/凭据文件
/var/lib/hp-printer/                 SQLite、接管身份、受限暂存文件
/var/log/ 或 journald                脱敏运行日志
```

运行用户只访问需要的目录和本地 CUPS 接口；管理权限通过限定 policy/受限 helper 验证。不授予整个服务无限 sudo 权限，不把服务长期作为 root 运行。systemd 设置重启退避、可写目录、资源上限；后端失败不停止 CUPS。

## 2. 网络与访问

用户已确认：实验室局域网电脑直接提交原生打印，管理员登录管理。部署时限定实际实验室网段，不默认开放其他接口；“局域网”不是可信个人身份，首版不据此提供准确个人统计。

| 入口 | 可访问者 | 设计 |
|---|---|---|
| SSH | 管理终端 | 保留既有访问；安装过程不能破坏连接 |
| CUPS 指定队列 | 批准的 LAN 地址/设备 | IPP/IPPS；限定目标队列与操作 |
| CUPS 管理/配置 | 本机或明确管理来源且认证 | 不因共享打印顺便开放管理权限 |
| ipp-usb 内部代理 | Pi 本机 | 保持 loopback 意图并验证访问限制；客户端不连接此端口 |
| hp-printer CLI/API | 管理员/受限服务身份 | 默认环回 API、SSH 到 Pi 运行 CLI；LAN API 需 HTTPS，令牌不放命令参数 |
| DNS-SD | 实际需要发现的局域网 | 可选；明确 URL 添加不依赖自动发现 |

原生打印 policy 要逐项测试 Print/Create/Send、Get-Jobs、Get-Job、Cancel/Hold/Release、CUPS-Get-Document 和配置修改权限。首版没有可信个人认证时，不把客户端自报的 `requesting-user-name` 当作本人取消他人任务或下载文件的依据；跨用户修改和完整历史仅管理员可见。CUPS 默认 owner 策略不能未经测试直接当作业务隔离。[CUPS policies](https://openprinting.github.io/cups/doc/policies.html)

部署预检可检测端口、证书和配置，但不得擅自关闭主机防火墙。共享只开放明确网段；不使用 `--remote-any` 当通用安装步骤。Pi 目前在两个网段上，IPv4/IPv6、LAN 和另一接口要分别核验。

地址优先使用实验室有线 LAN + DHCP 地址保留；不能把当前 eth0 的 `192.168.137.2` 当作已经具备此条件。暂时使用 Wi-Fi 时也应固定可解析入口，并测试 AP 客户端隔离和断线重连。

P1 实测暂以 Pi WLAN `192.168.5.87:631` 提供唯一 CUPS 队列，只允许 `192.168.5.0/24` 打印；此地址尚未确认 DHCP 保留。Windows 到 631 可达，管理配置返回 403；匿名 completed jobs 页面未列出本次任务，但 IPP `Get-Jobs`/`Get-Job` 权限仍待确认。ipp-usb 虽配置 loopback，实测监听 `*:60000`，当前由 systemd ExecStartPre 恢复 nftables 规则阻断非 loopback TCP 60000–65535。该手工实施和回退细节见 [P1 实测](verification/p1-20260929.md)。

## 3. 安装器契约

拟提供 `inspect`、`install`、`doctor`、`backup`、`upgrade`、`rollback`、`uninstall`。名称是计划，不表示脚本已存在。

安装顺序：

1. **预检**：确认平台、USB、指定队列、服务、Python/libcups、网络范围、可用磁盘、当前活动任务；输出将接管的对象。
2. **备份**：备份 CUPS 配置和 PPD、ipp-usb 配置、项目配置与当前版本信息；受限文件保留权限，备份目录只供管理员读取。不默认复制文档 spool。
3. **计划差异**：支持 dry-run，只展示脱敏差异；沿用队列名和设备 URI，遇到不同设备或无法识别的配置就报冲突。
4. **部署**：预检系统 libcups 和构建依赖，在最终版本目录内按锁文件执行 `uv sync --locked --no-dev --extra server --no-editable`，迁移数据库，配置专用用户和服务。不能复制 Windows .venv 到 Pi，也不把 uv 指向系统 Python 的 site-packages。只安装缺失依赖；系统安全更新走独立维护，不把全系统永久冻结。
5. **受控配置**：按实施阶段设置 CUPS 共享/策略，不覆盖整份 cupsd.conf。先 `cupsd -t` 检查，再在适当窗口应用变更；有处理中的作业时不强行重启。
6. **验证**：健康检查、只读 IPP 查询、权限拒绝用例、网络可达性、原有 USB 链路。真实打印使用单独显式测试入口。
7. **失败回退**：恢复此前版本与配置、检查健康和现有任务；不清空 spool，不删除公共队列后“重建试试”。

重复安装必须收敛到相同配置，不重复创建账户/队列/防火墙规则。并发安装采用本机锁。安装结果记录版本、改动清单、备份路径和验证结论，不记录认证秘密。

systemd 直接启动已部署环境中的 `.venv/bin/hp-printer serve`，使用绝对路径和显式配置文件；启动时不解析/升级依赖或访问包索引。uv 用于工程与部署准备，详细约定见 [CLI 与 uv](08-cli-and-uv.md)。

## 4. 升级、回滚与卸载

升级先验证数据库迁移与旧版本兼容性。向后不兼容迁移前用 SQLite backup API 或停写窗口制作一致备份，不能只复制活跃 WAL 数据库的主文件。代码切换失败可回旧版本；数据库回滚依赖明确备份，不擅自丢弃新增审计。

卸载默认仅移除 hp-printer 服务/产物，保留数据库和配置，保留系统 CUPS、ipp-usb、USB 队列和已排队任务。若本项目修改过共享/policy，依据安装清单提供恢复选项，先检查配置是否又被其他人修改。清除业务数据、删除队列或卸载系统打印软件需要明确选择。

## 5. 文件保留与容量

建议默认：应用上传暂存文件在 CUPS 已确认接收且关联稳定后删除；失败上传尽快清理；不确定提交的暂存文件最多保留 24 小时用于恢复；元数据和审计保留 30 天，最终值待用户确认。活动/未知任务不能仅因历史清理定时器到期而删除其恢复信息。

CUPS 单独控制文档和历史保留。计划完成任务不保留文件副本，需要显式配置并验证 `PreserveJobFiles`，不能假设系统默认满足；保留历史元数据与保存文档是两个设置。[cupsd.conf](https://openprinting.github.io/cups/doc/man-cupsd.conf.html)

容量保护同时覆盖 HTTP 上传和 CUPS 原生入口：最大请求大小、保留作业数/活跃作业数、可用磁盘低水位、日志轮转。初始建议低于 2 GiB 或低于总空间 10% 时停止新接收并告警；安装时按实机卷大小校准。项目因磁盘问题设置 reject 时记录原因，恢复不能覆盖管理员手动停收状态。

API 的 50 MiB 限制不等于 Windows 渲染后 spool 大小限制；原生打印另设置经过测试的请求/任务上限并给出可理解的拒绝提示。纸张页数预估和 CUPS 页计数都不作为准确计费基础。

## 6. 故障处理

| 场景 | 行为和诊断 | 避免的操作 |
|---|---|---|
| USB 断开/打印机断电 | 保留 CUPS 原任务，显示设备原因、最后观测时间；重连后查同一任务 | 自动复制任务到新队列 |
| 缺纸/卡纸 | 显示操作原因；管理员处理后恢复既有队列 | 按猜测页数自动续打 |
| CUPS 无响应 | CLI/API 返回降级和同步时间，提交不确定时对账 | 以 DB 列表为空判定打印完成 |
| 后端宕机 | 原生 CUPS 打印继续；恢复后全量对账 | 后端启动时重放旧提交 |
| Pi 断电 | 检查文件系统、spool 和设备，再确认作业状态 | 自动重打已输出但状态不明的文档 |
| 磁盘不足 | 拒收新任务并显示原因；保留活动作业 | 删除全部 spool 或全部历史解围 |
| 内部端口变化 | 按设备身份重查 ipp-usb 端点，核对配置与当前任务 | 把未验证的新设备自动绑定到旧队列 |
| IPP 重复属性 | CUPS 生产队列仍重复 `media-default`/`sides-default`；这台 Windows 的 Validate-Job/提交成功。保留严格检查作为回归门槛 | 把单次成功当成协议合规或其他客户端兼容 |

CUPS 的错误策略决定停机或重试行为，P1/P6 必须记录当前值并验证。优先避免不确定输出下的无界重试；必要时选择 stop-printer 等明确策略。应用不在 CUPS 原有恢复之外再造自动重打层。[lpadmin 错误策略](https://openprinting.github.io/cups/doc/man-lpadmin.html)

## 7. 诊断与维护

doctor 输出：软件版本、服务状态、指定队列身份/接受/暂停状态、USB 可见性、局域网入口、容量、同步延迟、脱敏错误摘要、最近操作结果。墨水和页计数标注采样时间，无法读取显示“未知”。

诊断包默认不含打印正文、完整标题、密码、令牌、设备序列号和私钥；可关联的网络定位信息明确标注为本地诊断用途。查询和日志读取范围有上限，不导出整机所有日志。

定期检查服务健康、磁盘、时钟和备份可恢复性。CUPS 报 completed 与用户肉眼看到完整出纸分开记录。发布前保存非敏感测试文件 hash、设备/系统版本和验证日期，使后续故障能复现。
